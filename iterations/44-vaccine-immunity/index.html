IMMUNITY

A coding vaccine is a named failure mode plus the executable check that makes a repository immune to it. The registry is the public repository Ventusltd/cvaa: one file per vaccine in vaccines/, named by a 12-digit timestamp, with front matter vaccine, generation, dose, superseded_by and five sections: Disease, Symptom, Antibody, Dose, Provenance. Each vaccine is a node on the ring, in timestamp order, the only order. Every file is read at commit —.

    2. What is this code used for?
    inoculate.mjs <repo> runs the antibodies against a repository: frontMatter reads each vaccine file; the registry is refused whole on any malformed name, front matter, section or lock mismatch; buildContext builds a data-only snapshot of the target; runAntibody runs each antibody in a child process with an empty environment, the Node permission model and a 5 s cap (through tools/antibody-runner.mjs); superseded vaccines are skipped; findings write SARIF, a job summary and the vaccines/last-fired.json sidecar, and exit 1. tools/selftest.mjs builds a CLEAN fixture and a DISEASED fixture per vaccine and requires every antibody to fire on its disease and stay silent on health.
