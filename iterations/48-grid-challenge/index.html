The elements catalogue asks: “how can this or that solve the next Grid Challenge?” Below is a fixed list of grid questions in plain engineering words. Open one: the page then fetches the catalogue (once) and lists the elements whose own title or description contains that question's search terms, next to the galaxy iteration that already demonstrates the question with a real engine module.

Questions
  1. How does this help draw a system or a single-line diagram? It draws nothing itself. It points each SLD question at candidate elements: substation (nearest-search question), cable route (route question), feeder current and voltage drop (feeder questions), circuit ratings (ratings question), demand and firm capacity (site questions). The data fields read are title, description, key, live and function_keys of each element in catalogue/elements.json, and name in catalogue/functions.json.
  2. What is this code used for? grid.mjs in this directory: QUESTIONS (the fixed list), matchElement() (whole-word, case-insensitive search of the element's own title and description), openQuestion() (fills one question once). Catalogue commit: . Callers: none in the estate; this page only (name-match inference over the iterations directory).
  3. Where does it lead next? ASSEMBLY opens the matched element in iteration 36 (?key=block:…), and the linked galaxy iteration runs the real engine module for the question. Whether an element truly answers a question is not established: a word match is not evidence of function.
Machine detail

Inputs: elements.json and functions.json at elements commit (fetched when the first question is opened; bounded queue of 4, 15 s timeout each, one promise per URL, a failed fetch can be retried). Per question: a list of search terms (words, case-insensitive, whole-word). Outputs: per question, a count of matched elements (counted at run time), each with its verbatim title and description, matched words highlighted, and buttons ASSEMBLY / APP. Refusals: EMPTY when no element's own words contain a term; FAIL with the network reason when a fetch fails; APP gives a reason when the element records no live address. No physical or electrical result is computed on this page.

Match counts: not yet counted (open a question).
