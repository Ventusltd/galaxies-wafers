    Questions
    1. How does this help draw a system or a single-line diagram?
    None yet. The federation map is a map of repositories, not of the grid: it draws no busbar, feeder, transformer, cable route, protection or earthing. What it gives a drawing is a trust check on the repositories that draw one. Nodes in the contents cartridge whose id names a drawing (name-match inference on sld, cable, grid, atlas): not yet known: open Nodes per status.
    2. What is the federation map used for?
    To make every repository a node and every dependency an edge with evidence. scripts/build_federation_map.py, run by .github/workflows/gridbot_federation_map_weekly.yml, scans the owner's repositories through GitHub API metadata and writes current/nodes.parquet, current/edges.parquet and weekly snapshots, checked with DuckDB; scripts/publish_federation_json.py writes the JSON reports; dashboard/federation_radial.html and live_sandbox/federation_control_ledger/app.js draw boards from live_sandbox/federation_control_ledger/data/*.json. This page: app.mjs countStatuses, greenWithoutEvidence, edgeEvidence, invariants. CODEAPP
    3. Where does it lead next?
    To the estate registry, which counts content and dependencies across every repository over time: 43 · registry growth. And to the spider that walks repositories into the galaxy of code: 32 · spider and galaxy.

    Machine detail. Inputs: config/status_rules.json (status words, meanings); DATA_CONTRACT.md (required fields, keys, invariants, read by hand into this page's checks); three node JSON files (properties.status, or rag); three edge JSON files; current/nodes.parquet and current/edges.parquet (zstd, read by hyparquet 1.30.1 with the fzstd 0.1.1 zstd decoder); reports/json/FEDERATION_MAP_LATEST.json. Every unit is a count of rows. Outputs: counts per status word; green nodes with no evidence field or an empty one; edges without evidencePath or evidenceText; invariants as MATCH, DIFFERS or NOT YET KNOWN. Refusals: a file that fails shows FAIL with its reason and every count from it stays not yet known. Names: nodes whose owner is not Ventusltd are counted, their names not displayed.
