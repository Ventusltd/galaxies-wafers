CHEMISTRY LEDGER

star-maker drove compositions of parts in a browser and recorded each as a star. A compound is one composition; its elements are the parts in it (a cartridge by symbol, with a version stamp when one was pinned). A compound decays when it produces an exception. Every number below is counted by this page from the published files when you open the ledger.

Questions
1. How does this help draw a system or a single-line diagram?
It draws no busbar, feeder, transformer, cable route, protection or earthing. It feeds the single-line panel indirectly: it shows which compositions of parts let the sld-sandbox cartridge (Ss, the part that draws the SLD panel) run. Counted from compounds[].decays[].text: the text sld-sandbox requires the sld-styles module appears in not yet known, and grid-scope requires the geodesy module in not yet known. Iteration 37 stated 702 compositions for the first; this page recounts it: not yet known.
2. What is this code used for?
This page: ledger.mjs parts, splitElement, countElements, readRules, isNoble, isRadioactive, drawableEdges, decayTotals, layout; drawn by app.mjs. It reads star-maker chemistry/compounds.json, chemistry/graph.json and CHEMISTRY.md at commit , files star-maker writes by arithmetic over its recorded stars (CHEMISTRY.md line 3: No model — arithmetic over the sky). Noble and radioactive are not fields in the JSON files; the rules are read from CHEMISTRY.md headings at run time: not yet known.
3. Where does it lead next?
To iterations/37-hidden-wires, which draws each decay text as a wire from the failing part to the module it names, and checks whether the register now declares it. Radioactive elements found here: not yet known.
