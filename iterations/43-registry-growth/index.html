HOW THE ESTATE GREW

The public registry Ventusltd/registry_of_all_content_in_repos_and_dependencies writes a new numbered snapshot each time its builder runs and never overwrites an old one. This page reads those snapshots as published, counts what is in them, and shows what changed between any two. Open a section: nothing is fetched before that.

What a snapshot holds. Each registry/registry_vNNNN.json carries schema_version, registry_version, generated_at, totals (repo_count, file_count, reachable_count, unreachable_count), boot_sequence[] (repo, path, reason) and repos[], each with name, role, default_branch, file_count, html_url, api_url and files[] of path, type, role, state, github_url, raw_url. A numbered snapshot has no edges. Edges exist only in graph_latest.json (nodes[] with id, label, kind, layer, x, y, source; edges[] with from, to, type; dataSource), built for the newest version only; latest.json is a pointer (authoritative_version, json_path, updated_at), not a copy. Section 4 checks the top-level snapshot field names against the newest served snapshot.

Read at commit of that repository, which was the head of origin/main when this page was built (fetched with git). Files come from raw.githubusercontent.com at that commit, so the counts do not move when the registry does; the check below says whether main has moved since.
