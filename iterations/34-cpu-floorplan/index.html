Illustrative architecture, not a model of any specific chip.

A real grid-engine module, read as text and cut into tokens, walked line by line through a classic five-stage pipeline (fetch, decode, execute, memory, write-back) as taught in Patterson and Hennessy. Everything drawn in the stages is derived from the source text by the tokenizer on this page.

Nothing is fetched until you ask. The keys come from the numbered database (LINES.md from the modular star): this page binary-searches it with small byte-range reads through a queue of at most three requests, each with a 15 s timeout, and reads one window of rows around the function's first line. The file is never downloaded whole.

A teaching mapping, not how JavaScript runs. A real JavaScript engine parses the source into bytecode for an interpreter, and a JIT compiler turns hot functions into machine code; only those machine instructions pass through a processor's pipeline, many of them per source line. Here each source line is treated as if it were one instruction so the stages can be seen.
