COUNTS THAT SAY THEMSELVES

The estate's grammar says every quantity is computed from live data, never typed, and missing data reads "not yet known". This page tests that rule against the count sentences the public pages publish. Open a section: it fetches each served page and each data file it names, finds the sentence and the line that makes it, recomputes the number from the data under the rule the code states, and prints MATCH, DIFFERS or NOT YET KNOWN. Digits written into a source file are marked typed. No colour here is a verdict.

              Questions
              1. How does this help draw a system or a single-line diagram?
              It draws no busbar, feeder, transformer, cable route, protection or earthing: none yet. It checks the sentences that tell a reader what a drawing draws, because a drawing that states a wrong count misleads the reader about what it draws. The fields it checks: blocks[] and blocks[].kind of stars blocks/blocks.json, the lists of blocks/families.json, families and lines of code/index.json, the rows of LINES.md, count of iterations/index.json, layers[] and layers[].features of layers/manifest.json, and counts of the elements catalogue.

              Machine detail · not yet known: open a section.

              Loading, as Grid Atlas does it: every section exists from the start and fetches nothing until opened; one queue of 4 carries every request, each with a 15 s timeout; one promise per URL, removed on failure so a retry is possible; only the changed row or label is rewritten. Closing a section keeps what was read.

              MATCH has a solid rule, DIFFERS a double rule, NOT YET KNOWN a dotted grey rule. Sources are read at main when a section opens, so a row changes when its file changes. every version
